本模块是 `app.gateway.routers.github_webhooks` 路由的唯一消费者，把入站 webhook 拆成纯函数 + 注册表 + 策略钩子的分层：
- `identity.py`：提供确定性的 LangGraph thread id（UUID5 命名空间）和从 payload 提取 `(repo, number)` 的无状态工具。
- `triggers.py`：纯函数触发器引擎，维护 `DEFAULT_TRIGGERS` 作为 per-event 字段级默认值，通过 Pydantic `exclude_unset` 合并 binding 覆盖；`event_should_fire` 返回 `(bool, reason)` 供日志使用。
- `prompts.py`：每个受支持 event 一个 `_xxx_prompt` 构建器，输出描述性 user prompt 并在末尾提示 agent 自行调用 `gh` CLI 写回。
- `registry.py`：扫描 `{base_dir}/users/{user_id}/agents/` 及遗留 `{base_dir}/agents/`，解析 `config.yaml` 中 `github:` 块并按 `(repo, event)` 建索引；以 `(user_id, agent_name, mtime)` 三元组为签名做进程内缓存，冷路径用 `asyncio.to_thread` 避免阻塞事件循环。
- `dispatcher.py`：编排入口 `fanout_event`——自环检测(`_is_self_event`)→ registry 查找 → trigger 过滤 → 构造 `InboundMessage` 并发布到 `MessageBus`，仅负责 fan-out，不直接调用 langgraph。
- `app_auth.py`：GitHub App 两阶段认证（RS256 App JWT → installation access token），带 per-installation `asyncio.Lock` 的双检锁缓存，TTL 55 分钟提前刷新。
- `run_policy.py`：向 `CHANNEL_RUN_POLICY["github"]` 注册 `ChannelRunPolicy`（非交互、默认 recursion_limit=250、fire_and_forget、无需 bound identity），并通过 `inject_github_credentials` 在运行时注入 `run_context["github_token"]`。
依赖方向单向：`dispatcher → {identity,triggers,prompts,registry}`，`run_policy` 仅在 import 时副作用注册自身，`app_auth` 被 `run_policy` 延迟导入以避免循环。
