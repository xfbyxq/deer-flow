四个 FastAPI `APIRouter` 文件各自注册一个子命名空间，统一挂载到网关主应用上；每个文件内按「Pydantic response/request 模型 → 内部工具函数 → 带装饰器的异步 handler」分层组织。

- console.py：只读报表层，直接通过 SQLAlchemy 2.0 查询 `RunRow` / `ThreadMetaRow` 并聚合 token 用量与成本估算；当底层为内存后端时 `_session_factory_or_503` 返回 503，避免对无持久化的运行时路径做侵入式修改。
- features.py：极简的启动期特性探测接口，仅读取 AppConfig 暴露给前端决定是否渲染 UI。
- skills.py：围绕 `SkillStorage` 的用户级技能 CRUD，区分 PUBLIC（写全局 `extensions_config.json` 并刷新所有用户缓存）与 CUSTOM/LEGACY（写 per-user `_skill_states.json` 并刷新单用户缓存），写入前经 `scan_skill_content` 安全扫描，变更通过 `append_history` 记录可回滚。
- suggestions.py：调用 `create_chat_model` 以 `suggest_agent` 身份生成追问，使用 `inject_langfuse_metadata` 注入 tracing 上下文，解析 LLM 输出的 JSON 列表作为最终结果。

权限方面，console 与 suggestions 使用 `@require_permission(...)` 装饰器进行资源级鉴权，skills 的管理类接口则通过 `require_admin_user` 强制管理员。依赖方向单向指向 `deerflow.*` 领域层与 `app.gateway.deps/authz`，本模块不持有业务状态。
