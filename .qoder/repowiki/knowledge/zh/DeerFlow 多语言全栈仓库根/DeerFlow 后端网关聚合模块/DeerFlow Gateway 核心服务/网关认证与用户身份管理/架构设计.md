模块按职责分层组织：
- 配置与模型：`config.py` 通过 Pydantic `AuthConfig` + 全局 `_auth_config` 单例加载 `AUTH_JWT_SECRET`（未设置时自动写入 `{base_dir}/.jwt_secret`），`models.py` 定义领域内 `User`/`UserResponse`。
- 令牌与密码：`jwt.py` 基于 PyJWT HS256 签发/解码带 `ver` 字段的 Token；`password.py` 暴露同步/异步哈希与校验函数。
- Provider 抽象层：`providers.py` 的 `AuthProvider` ABC 定义 `authenticate`/`get_user` 两个异步方法，`local_provider.py` 实现邮箱+密码流程并封装重哈希、OAuth 用户创建等用例。
- 存储抽象与实现：`repositories/base.py` 定义 `UserRepository` 接口（CRUD + `count_users`/`count_admin_users`/`get_user_by_oauth`），`repositories/sqlite.py` 通过共享 SQLAlchemy async session factory 操作 `deerflow.persistence.user.model.UserRow`，完成 ORM ↔ Pydantic 双向转换。
- OIDC 服务：`oidc.py` 的 `OIDCService` 独立承担发现、授权 URL 生成、code→token 交换、JWKS 缓存、ID Token 签名校验（RS*/ES*）、UserInfo 拉取与子串一致性校验，不依赖 Provider 或 Repository。
- 辅助工具：`oidc_state.py`、`credential_file.py`、`reset_admin.py`、`user_provisioning.py`、`errors.py` 分别处理 state 票据、凭据文件、管理员重置、初始用户注入与错误类型。
依赖方向：Provider → UserRepository → SQLAlchemy；OIDC 服务完全自包含；所有对外 API 由 `__init__.py` 统一 re-export。
