模块按职责分层组织：
- 抽象层 `base.py` 定义 `Channel` ABC（`start/stop/send` + 可选 `send_file` / `receive_file`），所有具体渠道实现均继承自它。
- 协议层 `message_bus.py` 通过 `MessageBus`（`asyncio.Queue` 实现的异步 pub/sub）解耦渠道与调度器，定义 `InboundMessage` / `OutboundMessage` / `ResolvedAttachment` 数据契约。
- 持久化层 `store.py` 以单 JSON 文件原子替换方式维护 `<channel>:<chat_id>[:topic_id] → thread_id` 映射；`runtime_config_store.py` 负责运行时配置合并。
- 调度核心 `manager.py` 中的 `ChannelManager` 消费 inbound queue，调用 Gateway 的 LangGraph SDK (`runs.wait` / SSE streaming) 驱动 agent，并回推 outbound 消息；内置去重（`_recent_inbound_events`）、线程并发锁、流式文本聚合、附件解析与安全路径白名单等逻辑。
- 生命周期编排 `service.py` 的 `ChannelService` 从 `config.yaml` 读取 channels 配置，通过 `_CHANNEL_REGISTRY` 字符串 import 路径动态加载各渠道类，管理其启停与热重载，并提供全局 `get_channel_service()` 单例。
- 策略与命令 `run_policy.py` 提供 per-channel 运行策略（recursion_limit、credentials_provider、是否可交互），`commands.py` 集中 `/connect` 绑定码与已知命令列表。
- 具体渠道适配器 `dingtalk.py`、`discord.py`、`feishu.py`、`github.py`、`slack.py`、`telegram.py`、`wechat.py`、`wecom.py` 各自实现 `Channel`，并通过 `register_inbound_file_reader` 向 manager 注册自定义文件下载器（如 wecom AES 解密、wechat 本地路径读取）。
依赖方向单向：adapter → base/message_bus/store → manager → service；manager 反向通过 `service.get_channel_service()` 查询能力元信息，避免循环导入。
