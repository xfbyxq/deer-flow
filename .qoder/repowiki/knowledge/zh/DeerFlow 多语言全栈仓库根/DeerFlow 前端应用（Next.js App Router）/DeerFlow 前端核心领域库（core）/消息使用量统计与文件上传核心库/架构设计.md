模块由两个并列子目录组成，分别承担不同职责：
- `messages/`：纯函数式工具层，围绕 LangGraph `Message` 类型工作。`usage.ts` 负责从 `usage_metadata` / `additional_kwargs.usage_metadata` 提取并聚合 TokenUsage；`utils.ts` 实现消息分组（human / assistant:processing / assistant / assistant:present-files / assistant:clarification / assistant:subagent）、推理内容拆分（`<think>...</think>` 流式安全处理）、隐藏控制消息过滤、内部标记标签剥离等；`usage-model.ts` 将后端 `token_usage_attribution` 规范化为前端可消费的 `TokenUsageAttributionAction` 联合类型，并据此生成调试步骤与本地化标签。
- `uploads/`：以 `api.ts` 暴露 REST 客户端（upload/list/delete/limits），通过 `../api/fetcher` + `getBackendBaseURL()` 访问 `/api/threads/{id}/uploads*`；`file-validation.ts` 在浏览器端做 `.app` bundle 识别与按 `UploadLimits` 的 max_file_size / max_files / max_total_size 预检；`hooks.ts` 基于 `@tanstack/react-query` 封装 useQuery/useMutation，统一 queryKey 前缀 `uploads` 并在 mutation 成功后 invalidate list；`prompt-inputFilePart.ts` 桥接 `ai` 包的 `FileUIPart` 到原生 `File`，支持 URL fallback 拉取。
依赖方向单向：hooks → api → fetcher/config；validation 仅依赖 api 的类型定义；messages 与 uploads 之间无直接依赖，仅共享 `FileInMessage` 这类与后端中间件产物协作的数据结构。
