模块由两个并列的领域包组成：
- `memory/`：纯数据层。`types.ts` 定义 `UserMemory` / `MemoryFact*` 等 DTO；`api.ts` 通过 `../api/fetcher` + `getBackendBaseURL()` 调用 `/api/memory*` REST 端点，统一用 `readMemoryResponse` 解析错误并抛出 Error；`hooks.ts` 基于 `@tanstack/react-query` 暴露 `useMemory`（queryKey=`["memory"]`）与各 mutation hook，所有 mutation 在 `onSuccess` 中用 `setQueryData(["memory"], memory)` 乐观回填，保持单一缓存源。
- `tasks/`：子任务运行时状态层。`context.tsx` 通过 `SubtaskContext` + `SubtasksProvider` 维护全局 `Record<string, Subtask>`，并用 `tasksRef` 指向最新 state，避免异步回调读到闭包快照；`subtask-update.ts` 提供纯函数 `computeNextSubtask`，将 `steps` 作为增量通过 `mergeSteps` 合并，返回 `{next, becameTerminal}` 供 hook 决定是否延迟渲染；`steps.ts` 定义可渲染的 `SubtaskStep`（`ai`/`tool` 两种），并提供 `messageToStep`（SSE 原始消息→step）、`eventsToSteps`（REST 事件→step）、`stepsForDisplay`（过滤空 AI 步/最终答案重复）；`api.ts` 的 `fetchSubtaskSteps` 以 `after_seq` 游标分页拉取 `/api/threads/:id/runs/:rid/events?event_types=subagent.step&task_id=...`，上限 100 页防死循环；`subtask-result.ts` 解析后端写入 `ToolMessage.additional_kwargs` 的结构化键（`subagent_status`/`subagent_error`/`subagent_result_brief`/`subagent_result_sha256`），兼容旧版文本前缀（`Task Succeeded.` 等），并将 `cancelled/timed_out/polling_timed_out/max_turns_reached` 折叠为前端三态之一。
依赖方向：`hooks.ts` → `api.ts` → `../api/fetcher`；`context.tsx` → `subtask-update.ts` → `steps.ts`；`api.ts` → `steps.ts`；`subtask-result.ts` 仅依赖类型，被上层消费。
