模块由两个并列的子目录组成，职责清晰、依赖单向：

- `sidecar/`：实现从 UI 引用片段到独立 Agent 线程的全链路。
  - `context.ts` 定义核心类型 `SidecarContext`（当前仅支持 `referenced_message`）并提供纯函数：`buildMessageSidecarContext`（从 LangChain Message 构造上下文）、`buildParentConversationContext`（截断并抽取最近 N 条可见消息作为 parent_conversation_context）、`buildSidecarContextPrompt`（将上下文序列化为带 XML 标签的 prompt 文本，并对属性值做 XML 转义）。
  - `thread.ts` 通过常量 `SIDECAR_METADATA_KEY = 'deerflow_sidecar'` 在 `AgentThread.metadata` 上标记侧边线程，并提供 `buildSidecarThreadMetadata` / `isSidecarThread` / `shouldShowInPrimaryThreadLists` 等元数据读写工具；保持 `referenced_message_ids`、`referenced_message_roles` 与 contexts 1:1 并行以支持同一源消息的多片段去重场景。
  - `reference-metadata.ts` 负责与后端序列化协议互转：`buildReferenceMessageMetadata` 输出 `referenced_message_contexts[]`，`readReferenceMessageContexts` 对 `additionalKwargs` 做白名单校验后还原为 `SidecarContext[]`。
  - `reference-state.ts` 提供 React 状态辅助：`appendSidecarReference` 按 `isSameSidecarContext` 去重追加，`getNextSidecarOpenState` 决定是追加到现有侧边会话还是新建。
  - `api.ts` 暴露 `createSidecarThread` 与 `findLatestSidecarThread`，前者使用模块级 `inFlightCreates: Map<string, Promise<AgentThread>>` 对同一 parentThreadId 的并发创建请求做 promise 合并，避免竞态产生重复子线程；后者通过 `threads.search(metadata={SIDECAR_METADATA_KEY:true, parent_thread_id})` 查找最新子线程。
  - `index.ts` 统一 re-export，对外只暴露聚合 API。

- `suggestions/`：独立的“智能建议”功能入口。
  - `api.ts` 调用 `/api/suggestions/config` 获取 `enabled` 开关，遇到 404 时回退为 `true` 以兼容旧后端。
  - `hooks.ts` 用 `@tanstack/react-query` 的 `useQuery` 缓存该配置（`staleTime: Infinity`）。
  - `placeholders.ts` 维护与 i18n 模板同步的正则 `SUGGESTION_TEMPLATE_PLACEHOLDER_PATTERN`，并提供 `findSuggestionTemplatePlaceholder` 返回未替换占位符的字符区间。

依赖方向：`sidecar/api.ts` → `thread.ts` → `context.ts`；`reference-metadata.ts` 与 `reference-state.ts` 仅依赖 `context.ts`；`suggestions/` 与 `sidecar/` 相互独立，均通过 `@/core/api/fetcher` 和 `@/core/config` 访问后端。
