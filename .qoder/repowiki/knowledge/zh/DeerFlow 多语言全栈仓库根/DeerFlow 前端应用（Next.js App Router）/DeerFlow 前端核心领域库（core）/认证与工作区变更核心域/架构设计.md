模块由两个并列的子目录组成，分别对应 RFC-001 的两个独立领域：

- `auth/`：围绕 `AuthProvider.tsx` 暴露 React Context + `useAuth` / `useRequireAuth` hooks，仅持有展示型 `User`（不含 JWT），通过 `/api/v1/auth/me` 与 `/api/v1/auth/logout` 交互；SSR 侧由 `server.ts` 的 `getServerSideUser()` 基于 Next.js `cookies()` 读取 `access_token` 并返回 tagged union `AuthResult`（authenticated / needs_setup / system_setup_required / unauthenticated / gateway_unavailable / config_error），调用方必须穷尽 switch 处理；`types.ts` 用 zod `userSchema` 作为用户模型唯一来源，`parseAuthError` 统一解析 FastAPI 多种错误信封；`setup.ts` 封装 setup-status 探测；`gateway-config.ts`、`proxy-policy.ts`、`static-user.ts`、`auth-disabled-user.ts` 是运行时模式开关（静态站点、禁用认证等）。
- `workspace-changes/`：纯数据层，`api.ts` 通过 `getBackendBaseURL()` 拼接 `/api/threads/{id}/runs/{id}/workspace-changes`；`hooks.ts` 基于 `@tanstack/react-query` 暴露 `useWorkspaceChanges` 与 `workspaceChangesQueryKey`，默认 5 分钟 staleTime、不重试、不 refetchOnWindowFocus；`summary.ts` 提供无副作用的 diff 行分类（addition/context/deletion/hunk/meta）、文件计数与排序工具；`types.ts` 定义 `WorkspaceChangesResponse`、`WorkspaceFileChange` 等接口。

依赖方向：`auth/server.ts` → `gateway-config` / `auth-disabled-user` / `static-user` / `types`；`auth/AuthProvider` → `../static-mode` + `./types`；`workspace-changes/*` → `@/core/config` + 彼此内部类型，两者互不依赖。
