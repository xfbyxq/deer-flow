本模块按职责拆分为五个文件，形成清晰的自底向上分层：
- `types.ts`：定义后端 DTO `ScheduledTask` / `ScheduledTaskRun` 及 payload 类型，作为整个模块的类型契约。
- `api.ts`：纯 HTTP 客户端，通过 `scheduledTasksUrl(path)` 拼接 `/api/scheduled-tasks/*` 路由，统一使用 `@/core/api/fetcher` 发起请求并以 `throwGatewayApiError` 抛错；不持有状态。
- `hooks.ts`：基于 `useQuery` / `useMutation` 封装 CRUD、暂停/恢复、触发、运行记录等查询与变更操作，统一在 `onSuccess` 中 invalidate `scheduled-tasks`、`scheduled-tasks/thread`、`scheduled-tasks/runs` 三类 queryKey，并在 `onError` 中通过 `sonner.toast.error` + i18n key 提示用户。
- `cron.ts`：无外部依赖的纯函数库，维护 `CronPreset`（hourly/daily/weekly/monthly/custom）与 `ScheduleFormState` 表单模型，提供 `serializeCron` ↔ `parseCron` 双向转换、`describeSchedule` 多语言描述，以及 `zonedLocalToUtcIso` / `utcToZonedLocalInput` 处理 datetime-local 与时区的 DST 安全往返。
- `recipes.ts`：仅前端存在的启动模板数组，包含 trending/news/issues/weekly 四个预设 prompt 与默认 cron 调度，供 UI 一键创建任务。

依赖方向：`hooks.ts → api.ts → types.ts`；`recipes.ts` 仅消费上层组件暴露的 `ScheduleValue` 类型；`cron.ts` 被 UI 层直接消费，不反向依赖其他文件。
