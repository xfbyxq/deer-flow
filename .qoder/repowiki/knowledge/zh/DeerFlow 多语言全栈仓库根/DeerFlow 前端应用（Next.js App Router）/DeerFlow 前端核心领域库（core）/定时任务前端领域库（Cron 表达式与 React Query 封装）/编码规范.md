- 所有 API 函数统一通过 `scheduledTasksUrl(path)` 拼接 URL，并对非 `response.ok` 走 `throwGatewayApiError` 抛出带上下文的错误信息。
- 每个 `useMutation` hook 在 `onSuccess` 中显式 invalidate 相关 queryKey（如 `scheduled-tasks`、`scheduled-tasks/thread`、`scheduled-tasks/runs/<id>`），保证列表与详情一致。
- 错误提示一律组合 i18n key（`t.scheduledTasks.errors.*`）与 `error.message`，并通过 `sonner.toast.error` 展示，不在业务逻辑里硬编码文案。
- Cron 表达式采用“生成即信任”的策略：`serializeCron` 只输出我们控制的规范形式，`parseCron` 对无法识别的模式回退到 `custom` + `raw`，避免引入通用 cron 解析器。
- 表单状态集中在 `ScheduleFormState` 结构体中，由 `cron.ts` 的纯函数在表单值与后端 `schedule_spec` 之间互转，UI 层不直接操作 cron 字符串。
