模块由两个并列子目录组成：
- `core/i18n`：以 `locales/types.ts` 中的 `Translations` 接口为契约，`locales/en-US.ts`、`locales/zh-CN.ts` 分别实现具体文案；`translations.ts` 将二者聚合为 `Record<Locale, Translations>`；`locale.ts` 集中声明 `SUPPORTED_LOCALES`、`DEFAULT_LOCALE`、`detectLocale`、`normalizeLocale` 等语言检测与归一化逻辑。
- 运行期状态通过 React Context 管理：`context.tsx` 暴露 `I18nProvider` + `useI18nContext`，并在切换时写入 `document.cookie`；`hooks.ts` 封装 `useI18n`，在组件挂载时优先读取客户端 cookie，否则回退到浏览器 `navigator.language`，并同步写回 cookie。
- 服务端侧（SSR / Server Components）走独立路径：`server.ts` 使用 `next/headers` 的 `cookies()` API 读写 `locale`，并提供 `getI18n(localeOverride?)` 返回 `{ locale, t }`，供页面级 RSC 使用。
- `cookies.ts` 同时提供客户端 (`document.cookie`) 与服务端 (`import('next/headers')` 动态导入) 两套 cookie 读写工具，避免在顶层直接耦合 Next.js 运行时。
- `core/config/index.ts` 是独立的运行时配置层，仅依赖 `@/env` 提供的 `NEXT_PUBLIC_*` 变量，通过 `URL(base, origin)` 拼接后端与 LangGraph 的基础地址，SSR 下回退到 `http://localhost:2026`。
- 依赖方向单向：`hooks.ts` → `context.tsx` → `cookies.ts` → `translations.ts` → `locales/*`；`server.ts` 与 `hooks.ts` 各自独立消费 `translations`，互不引用。
