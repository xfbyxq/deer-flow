目录按职责划分为四个子包，依赖方向自下而上：
- `ui/`：纯展示型原子组件（Button、Input、Dialog、Sidebar 等），全部通过 `class-variance-authority` 声明 variant/size 变体，使用 `@radix-ui/*` 作为无样式交互基座，并通过 `data-slot` / `data-variant` / `data-size` 属性配合 Tailwind 选择器实现主题化；不持有业务状态。
- `ai-elements/`：面向 AI 对话与可视化画布的富交互组件（canvas、node、edge、connection、streamdown、message 等），多为客户端组件（顶部 `'use client'`），封装了流式渲染、错误降级（如 Streamdown 递归栈溢出回退为 pre）等策略。
- `workspace/`：工作区业务层组件，按功能再分子目录（artifacts、messages、settings、sidecar、channels、citations、agents、changes、chats）。每个子目录通过 `index.ts` 做 barrel 聚合导出，并配套独立的 Context（如 `artifacts/context.tsx`、`messages/context.ts`、`sidecar/context.tsx`）管理跨组件状态，由上层容器组合。
- `landing/` 与 `docs/`：面向营销页与文档站的页面级布局与内容组件，相对独立于运行时逻辑。
- 根级 `theme-provider.tsx` 与 `query-client-provider.tsx` 是应用级 Provider 入口，分别基于 `next-themes` 与 React Query 注入全局能力。
依赖方向：`workspace` → `ai-elements` → `ui`；`ai-elements` 与 `workspace` 均通过 `@/lib/utils`（cn）、`@/env`、`@/core/*` 访问工具与环境，不反向依赖上层页面。
