模块以 Next.js App Router 的目录即路由约定组织：
- `app/layout.tsx` 为根布局，注入 ThemeProvider 与 I18nProvider；`page.tsx` 是着陆页。
- `(auth)` 路由组集中处理登录、回调、初始化流程，其 `layout.tsx` 通过 `getServerSideUser()` 的结果 tag 做分流（authenticated→重定向到 /workspace，needs_setup→允许 setup，unauthenticated/gateway_unavailable→渲染对应 UI）。
- `workspace/` 是受保护的工作区入口，`layout.tsx` 同样校验身份并包裹 WorkspaceContent 侧边栏布局；`page.tsx` 在静态演示模式下 (`NEXT_PUBLIC_STATIC_WEBSITE_ONLY=true`) 扫描 `public/demo/threads/` 下首个 thread 目录并重定向，否则跳转到 `/workspace/chats/new`。
- `chats/[thread_id]/` 使用 `generateStaticParams` 在静态模式下预生成 demo 线程参数，`providers.tsx` 提供聊天上下文，`page.tsx` 作为客户端组件承载消息流、输入框、侧车、导出等功能。
- `agents/`、`scheduled-tasks/` 并列子路由复用 workspace layout。
- `blog/`、`[lang]/docs/` 使用 MDX 动态路径 `[[...mdxPath]]` 渲染文章与文档。
- `api/memory/` 下的 `route.ts` 与 `[...path]/route.ts` 实现通用反向代理，将请求转发至 `NEXT_PUBLIC_BACKEND_BASE_URL`（默认 `http://127.0.0.1:8001`），删除 host/connection/content-length 后透传 body。
- `mock/api/` 提供本地模拟数据接口（mcp/config、models、skills、threads），用于无后端开发或演示模式。
依赖方向：页面 → components/workspace/* → core/*/hooks → api/mock|api/memory 代理 → 外部后端；认证状态由 `core/auth/server.getServerSideUser` 在服务端统一读取。
