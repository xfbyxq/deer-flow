模块以 `__init__.py` 暴露统一入口 (`build_server_params`, `build_servers_config`, `get_mcp_tools`, `initialize_mcp_tools`, `get_cached_mcp_tools`, `reset_mcp_tools_cache`)，内部按职责拆分为四个子文件：
- `client.py`：纯配置构建器，将 `ExtensionsConfig.McpServerConfig` 翻译为 `langchain-mcp-adapters.MultiServerMCPClient` 所需的 `{transport, command|url, args|headers}` 参数字典。
- `tools.py`：核心装配层。通过 `MultiServerMCPClient` 发现各 server 的 LangChain `BaseTool`，对 stdio transport 的工具用 `_make_session_pool_tool` 包装成带持久会话的 `StructuredTool`；同时把 MCP `CallToolResult` 转换为 LangChain `content_and_artifact` 格式，并在转换阶段把 stdio 子进程产生的本地文件路径（含自由文本中的裸文件名）重写到 `/mnt/user-data/...` 虚拟路径，使 sandbox/artifact API 可访问。
- `session_pool.py`：实现 `MCPSessionPool`，以 `(server_name, scope_key)` 为键维护 LRU 持久 `ClientSession`，每个 session 由独立的 `_run_session` 任务拥有，确保 anyio cancel-scope 的 enter/exit 在同一 task 中完成，避免跨 loop/task 关闭导致的 `RuntimeError`；提供 `close_scope` / `close_server` / `close_all` / `close_all_sync` 多种清理语义，并以全局单例 `get_session_pool()` 暴露。
- `oauth.py`：`OAuthTokenManager` 按 server 维度缓存/刷新 OAuth token（支持 `client_credentials` 与 `refresh_token`），并通过 `build_oauth_tool_interceptor` 返回一个 `langchain_mcp_adapters.interceptors.MCPToolCallRequest` 拦截器，在每次调用前注入 `Authorization` 头；`get_initial_oauth_headers` 用于连接建立时预填 header。
- `cache.py`：基于配置文件 mtime 的惰性缓存，`initialize_mcp_tools` 在应用启动时一次性加载，`get_cached_mcp_tools` 在 FastAPI/LangGraph Studio 两种上下文下自动选择事件循环策略，并在 config 变更时触发 `reset_mcp_tools_cache` 重建。
依赖方向：`cache → tools → (client | oauth | session_pool)`，`__init__.py` 仅做 re-export，无业务逻辑。
