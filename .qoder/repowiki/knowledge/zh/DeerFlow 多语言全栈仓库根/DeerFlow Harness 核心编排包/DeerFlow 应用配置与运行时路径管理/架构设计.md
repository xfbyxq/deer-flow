模块以 `AppConfig`（`app_config.py`）为根聚合类，组合 `ModelConfig`、`ToolConfig`、`ToolGroupConfig`、`MemoryConfig`、`GuardrailsConfig`、`CheckpointerConfig`、`StreamBridgeConfig`、`SubagentsAppConfig`、`ACP*Config`、`AgentsApiConfig`、`SchedulerConfig`、`RunEventsConfig`、`DatabaseConfig`、`SandboxConfig`、`AuthAppConfig`、`LoopDetectionConfig`、`ReadBeforeWriteConfig`、`SafetyFinishReasonConfig`、`CircuitBreakerConfig`、`LoggingConfig`、`TokenUsageConfig`、`TokenBudgetConfig`、`TitleConfig`、`SummarizationConfig`、`SuggestionsConfig`、`ChannelConnectionsConfig`、`ExtensionsConfig`、`SkillEvolutionConfig`、`SkillsConfig`、`ToolOutputConfig`、`ToolSearchConfig` 等子配置段；每个子段独立成文件并通过 `load_*_config_from_dict` 工厂函数暴露“从 dict 重建全局单例”的能力。

- 配置来源：`AppConfig.from_file` 按优先级解析 `config.yaml`（参数 → `DEER_FLOW_CONFIG_PATH` → 调用者项目根 → legacy `backend/config.yaml` / repo 根），通过 `_check_config_version` 对比同目录 `config.example.yaml` 的 `config_version` 并告警，再经 `resolve_env_variables` 递归展开 `$VAR` 占位符，最后 `model_validate` 生成强类型对象。
- 热重载：`get_app_config()` 维护进程级缓存，通过 `_get_config_signature`（mtime + size + sha256）检测变更自动 reload；`push_current_app_config` / `pop_current_app_config` 借助 `ContextVar` 提供协程作用域覆盖，支持测试与嵌套运行。
- 启动边界：`reload_boundary.py` 集中声明 `STARTUP_ONLY_FIELDS`（如 `database`、`checkpointer`、`run_events`、`stream_bridge`、`sandbox`、`log_level`、`logging`、`channels`、`channel_connections`、`scheduler`），配合 `format_field_description` 在 IDE hover 中显式标注“需重启”，并由测试保证注册表与 schema description 双向一致。
- 路径子系统：`paths.py` 的 `Paths` 类封装宿主/沙箱双视图路径（`base_dir`、`thread_dir`、`sandbox_work_dir`、`sandbox_uploads_dir`、`sandbox_outputs_dir`、`acp_workspace_dir` 等），通过 `VIRTUAL_PATH_PREFIX=/mnt/user-data` 将沙箱虚拟路径映射回宿主目录，并提供 `ensure_thread_dirs` 以 0o777 权限创建以便跨 UID 容器写入；`runtime_paths.py` 提供 `existing_project_file` / `runtime_home` 作为默认基目录发现策略。
- 依赖方向：本模块仅被上层 runtime/gateway 消费，自身不反向 import 业务逻辑；对 `deerflow.runtime.checkpointer`、`deerflow.runtime.store` 的导入延迟到 `_apply_singleton_configs` 内部以避免循环依赖。
