模块以 `factory.create_chat_model` 为唯一对外入口（由 `__init__.py` 暴露），通过 `deerflow.reflection.resolve_class` 根据配置中的 `use` 字段解析并实例化具体 Provider 类。

内部分层：
- 工厂与配置注入层：`factory.py` 负责从 AppConfig 读取 ModelConfig，执行 thinking/reasoning_effort/when_thinking_enabled 的合并策略，对 OpenAI 兼容路径做 `api_base→base_url` 归一化、默认 `stream_usage=True`、`stream_chunk_timeout=240s` 注入，以及未知参数告警；同时按 provider 类型追加特殊逻辑（Codex 映射 reasoning_effort、MindIE 限制 max_retries）。
- Provider 实现层：每个文件对应一个 LangChain ChatModel 子类——`claude_provider:ClaudeChatModel`（继承 ChatAnthropic，支持 OAuth Bearer + prompt caching + thinking budget）、`vllm_provider:VllmChatModel`（继承 ChatOpenAI，保留 vLLM reasoning 字段跨轮次）、`mindie_provider:MindIEChatModel`（继承 ChatOpenAI，XML tool call 编解码 + 流式回退）、`openai_codex_provider:CodexChatModel`（直接实现 BaseChatModel，调用 chatgpt.com/backend-api/codex/responses SSE）。`patched_*.py` 提供第三方库的补丁替换。
- 共享基础设施：`credential_loader.py` 集中实现 Claude Code / Codex CLI 凭据自动发现；`assistant_payload_replay.py` 提供 `restore_assistant_payloads` 通用助手，供 vLLM 等 Provider 在 `_get_request_payload` 中把 AIMessage 上的 provider 特定字段写回序列化 payload。

依赖方向：Provider → credential_loader / assistant_payload_replay；factory → Provider + deerflow.config + deerflow.tracing；Provider 之间互不依赖，仅通过统一的 BaseChatModel 接口被上层消费。
