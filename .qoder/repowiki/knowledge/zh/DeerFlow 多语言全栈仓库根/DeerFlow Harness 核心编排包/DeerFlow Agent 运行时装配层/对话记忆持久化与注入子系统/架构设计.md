模块按职责划分为四个子层，通过全局单例工厂对外暴露：
- `storage.py`：定义 `MemoryStorage` ABC 与默认实现 `FileMemoryStorage`（带 mtime 失效的进程内缓存 + 原子 tmp+rename 写入），并通过 `get_memory_storage()` 按配置动态 import 自定义存储类；同时提供 `create_empty_memory()` 作为内存结构契约。
- `message_processing.py`：纯函数工具集，负责过滤上传块/隐藏消息、检测用户纠正与正向强化信号，供 hook 与 updater 复用。
- `queue.py`：`MemoryUpdateQueue` 基于 `threading.Timer` 的 debounce 队列，对同一 `(thread_id, user_id, agent_name)` 合并最近对话，后台线程调用 `MemoryUpdater.update_memory` 执行更新，并在 Timer 线程中显式 rebind `deerflow_trace_id` 以维持 tracing。
- `updater.py`：核心编排器 `MemoryUpdater`，构造 prompt → 调用 `create_chat_model(...thinking_enabled=False)` 同步 invoke → `_parse_memory_update_response` 解析 JSON → `_apply_updates` 应用摘要/事实增删 → 经 `_strip_upload_mentions_from_memory` 清理后落盘；并提供 `update_memory_from_conversation` 等便捷函数。
- `prompt.py`：集中存放 `MEMORY_UPDATE_PROMPT` / `FACT_EXTRACTION_PROMPT` / `STALENESS_REVIEW_PROMPT` 模板以及 `format_memory_for_injection`（支持 guaranteed-category 分预算的事实选择、tiktoken/CJK-aware 估算、安全截断）和 `format_conversation_for_update`。
- `summarization_hook.py`：注册为 SummarizationMiddleware 钩子，在消息即将被总结时把过滤后的对话丢入 queue，是外部进入本模块的唯一入口。
依赖方向：hook → message_processing + queue → updater → storage/prompt/config/models；`__init__.py` 统一导出所有公共 API。
