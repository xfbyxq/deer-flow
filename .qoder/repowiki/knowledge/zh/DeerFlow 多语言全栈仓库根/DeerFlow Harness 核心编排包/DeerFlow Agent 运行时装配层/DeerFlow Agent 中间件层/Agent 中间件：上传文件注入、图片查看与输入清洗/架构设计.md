三个独立的 `langchain.agents.middleware.AgentMiddleware` 子类，分别挂载到不同钩子点，职责互不依赖：
- `uploads_middleware.py` 的 `UploadsMiddleware` 实现 `before_agent`/`abefore_agent`，从当前 HumanMessage 的 `additional_kwargs.files` 读取新上传文件，扫描线程 uploads 目录收集历史文件，按查询匹配强度排序后生成 `<uploaded_files>` 块并前置到用户消息内容（支持字符串与多模态 content-block list），同时将原始文本写入 `ORIGINAL_USER_CONTENT_KEY`；阻塞式 IO 通过 `run_in_executor` 派发。
- `view_image_middleware.py` 的 `ViewImageMiddleware` 实现 `before_model`/`abefore_model`，检测上一条 AIMessage 是否包含已完成的 `view_image` tool_call，若是则构造含 base64 image_url 的 HumanMessage 注入 state，供 LLM 直接“看到”图片。
- `input_sanitization_middleware.py` 的 `InputSanitizationMiddleware` 实现 `wrap_model_call`/`awrap_model_call`，定位最后一个非系统注入的 HumanMessage，用正则把受保护标签名（如 system、memory、uploaded_files 等）HTML 转义，并用 `--- BEGIN USER INPUT ---` / `--- END USER INPUT ---` 包裹，防止 prompt-injection 同时保留用户意图。

状态约定：所有中间件注入的系统消息统一通过 `additional_kwargs={"hide_from_ui": True}` 标记，以便下游过滤；被注入的原始用户文本通过 `ORIGINAL_USER_CONTENT_KEY` 保存，保证幂等与可恢复。
