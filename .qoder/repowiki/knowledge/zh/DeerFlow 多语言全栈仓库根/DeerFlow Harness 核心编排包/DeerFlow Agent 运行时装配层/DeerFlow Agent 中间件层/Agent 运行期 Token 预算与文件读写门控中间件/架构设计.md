三个独立的 `langchain.agents.middleware.AgentMiddleware` 子类，分别挂载到不同钩子点：
- `TokenUsageMiddleware.after_model`：在每次模型响应后扫描消息历史，从 `task_tool.pop_cached_subagent_usage` 中把子代理的 usage 合并回发起该 AIMessage 的父消息（通过 tool_call_id 反向查找），并对最后一条 AIMessage 附加 `token_usage_attribution` 元数据（step kind / actions / shared_attribution）。
- `TokenBudgetMiddleware.after_model + wrap_model_call`：以 run_id 为键维护 `_cumulative_usage`、`_seen_messages`、`_warned`、`_pending_warnings` 四个 `BoundedDict`（LRU 上限 1000，防止 abandoned run 泄漏），在 `after_model` 计算 input/output/total 相对上次 seen 的增量并比较 warn/hard_stop 阈值；硬截断时剥离 AIMessage.tool_calls 并改写 finish_reason，警告则延迟到下一次 `wrap_model_call` 前注入为 `HumanMessage(name="budget_warning")`，从而不破坏 AIMessage→ToolMessage 配对。
- `ReadBeforeWriteMiddleware.wrap_tool_call/awrap_tool_call`：对 `write_file`/`str_replace` 执行前读取沙箱当前内容并与消息历史中最近一次 `read_file` 的 sha256 标记比对，不一致则返回错误 ToolMessage；读成功时在 ToolMessage.additional_kwargs 上打 `{path, hash}` 标记，所有状态仅存于 state["messages"]，并通过 per-(scope,path) 的 `WeakValueDictionary` 锁串行化同一 turn 内的并发工具调用。
依赖方向单向向外：仅依赖 `deerflow.config.token_budget_config.TokenBudgetConfig`、`deerflow.tools.builtins.task_tool` 和 `deerflow.sandbox.tools.read_current_file_content`，不反向被这些模块引用。
