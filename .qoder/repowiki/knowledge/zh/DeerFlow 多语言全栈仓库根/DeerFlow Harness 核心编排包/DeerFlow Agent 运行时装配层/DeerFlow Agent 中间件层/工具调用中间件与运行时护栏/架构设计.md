本模块以 `langchain.agents.middleware.AgentMiddleware[AgentState]` 为统一扩展点，每个文件实现一个独立的中间件类，通过 `wrap_model_call`/`awrap_model_call`（拦截模型请求）、`wrap_tool_call`/`awrap_tool_call`（拦截工具执行）和 `after_model`/`aafter_model`（结果后处理）三类钩子组合成可插拔的执行链。

- 共享基础设施：`tool_call_metadata.py` 暴露 `clone_ai_message_with_tool_calls`，用于在修改 AIMessage.tool_calls 时同步 `additional_kwargs.tool_calls` 与 `response_metadata.finish_reason`，被 `SubagentLimitMiddleware` 复用以避免破坏 provider 原始元数据。
- 运行时组装器：`tool_error_handling_middleware.py` 中的 `_build_runtime_middlewares` / `build_lead_runtime_middlewares` / `build_subagent_runtime_middlewares` 是唯一的装配入口，按三层顺序拼接中间件：外层 wrap_model_call（InputSanitization → ToolOutputBudget）、线程级 before_agent（ThreadData/Uploads/Sandbox）、尾部 post-processing（DanglingToolCall → LLMErrorHandling → Guardrail → SandboxAudit → ReadBeforeWrite → ToolErrorHandling），并依据配置条件性注入 ViewImage、LoopDetection、SafetyFinishReason、DeferredToolFilter 等。
- 职责边界：
  - `DanglingToolCallMiddleware`：在 `wrap_model_call` 扫描历史消息，为缺少对应 ToolMessage 的 AIMessage 插入占位错误 ToolMessage，确保 OpenAI 兼容校验通过；同时处理 `invalid_tool_calls` 与 provider raw payload。
  - `DeferredToolFilterMiddleware`：基于构造期传入的 `deferred_names` + 运行期 `state['promoted']`（按 catalog_hash 作用域）从 `request.tools` 中剔除尚未 promoted 的工具 schema，并在 `wrap_tool_call` 阶段直接返回错误 ToolMessage 阻断执行。
  - `ToolOutputBudgetMiddleware`：在 `wrap_tool_call` 对 ToolMessage/Command.update.messages 做 head+tail 截断或持久化到 `/mnt/user-data/outputs`（优先 host-mounted sandbox，否则写入 sandbox 文件系统），并通过 `wrap_model_call` 对历史 ToolMessage 做二次兜底截断；I/O 路径通过 `asyncio.to_thread` 避免阻塞事件循环。
  - `ToolErrorHandlingMiddleware`：捕获除 `GraphBubbleUp` 外的所有异常，转为带结构化 `additional_kwargs` 的 error ToolMessage，并对 skill read 成功结果追加 `SKILL_CONTEXT_ENTRY_KEY` 元数据。
  - `SubagentLimitMiddleware`：在 `after_model` 阶段裁剪单条 AIMessage 中超过 `MAX_CONCURRENT_SUBAGENTS`（钳制到 [2,4]）的 `task` 工具调用。

依赖方向：本模块只向上依赖 `deerflow.config.*`、`deerflow.sandbox.*`、`deerflow.subagents.*` 以及 LangChain/LangGraph 类型，不反向被其他中间件引用，由上层 agent 构建器按需拼装。
