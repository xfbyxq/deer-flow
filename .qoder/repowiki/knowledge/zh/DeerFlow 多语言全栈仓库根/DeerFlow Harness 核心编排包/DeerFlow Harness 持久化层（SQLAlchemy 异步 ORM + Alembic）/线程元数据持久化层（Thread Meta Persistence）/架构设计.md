模块采用「接口 + 多实现」的分层设计：
- `base.py` 定义抽象基类 `ThreadMetaStore` 及异常 `InvalidMetadataFilterError`，所有 CRUD/查询方法统一接受三态 `user_id`（`AUTO`/显式字符串/`None`），通过 `deerflow.runtime.user_context.resolve_user_id` 解析上下文所有者。
- `model.py` 声明 ORM 模型 `ThreadMetaRow`，映射到 `threads_meta` 表，字段含 `thread_id`(PK)、`assistant_id`、`user_id`、`display_name`、`status`、`metadata_json`(JSON)、时间戳等，继承自 `deerflow.persistence.base.Base`。
- `sql.py` 中的 `ThreadMetaRepository` 是 SQL 实现，使用 `async_sessionmaker[AsyncSession]` 管理事务；`search` 借助 `deerflow.persistence.json_compat.json_match` 对 JSON 列做安全键过滤，非法键抛出 `InvalidMetadataFilterError`；`check_access` 区分 `require_existing` 两种语义以兼容删除后的幂等边界。
- `memory.py` 中的 `MemoryThreadMetaStore` 将同一套 API 适配到 LangGraph Store 的 `("threads",)` 命名空间，内部 `_get_owned_record` 复用 owner 校验逻辑，并通过 `coerce_iso` 兼容旧 Gateway 写入的 unix 秒时间戳。
- `__init__.py` 暴露工厂函数 `make_thread_store(session_factory, store)`，根据是否传入 `session_factory` 在 SQL 与内存实现间切换，并统一导出 `ThreadMetaStore`、`ThreadMetaRepository`、`MemoryThreadMetaStore`、`ThreadMetaRow` 与异常类型。
