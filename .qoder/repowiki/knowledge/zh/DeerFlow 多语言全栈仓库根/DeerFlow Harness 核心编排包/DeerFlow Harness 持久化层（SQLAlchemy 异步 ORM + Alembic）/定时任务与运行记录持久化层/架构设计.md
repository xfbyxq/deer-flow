模块按实体拆分为两个并列子包：`scheduled_tasks/` 对应 `scheduled_tasks` 表，`scheduled_task_runs/` 对应 `scheduled_task_runs` 表；每个子包遵循统一三层结构——`model.py` 定义继承自 `deerflow.persistence.base.Base` 的 ORM Row 类，`sql.py` 实现同名 Repository 类封装所有异步 SQL 操作，`__init__.py` 仅 re-export Row 与 Repository。

- 依赖方向：Repository → ORM Row → Base，不反向依赖上层业务；通过构造注入 `async_sessionmaker[AsyncSession]` 获取会话，避免全局 DB 单例。
- 并发与一致性：`claim_due_tasks` 使用 `with_for_update(skip_locked=True)` 在数据库层面做行级锁抢占，配合 `lease_owner` / `lease_expires_at` 字段实现多实例安全租约；`update_after_launch` 与 `update_status` 均支持 `protect_terminal` 参数以处理完成钩子与启动路径之间的竞态。
- 状态机：任务侧用 `TERMINAL_TASK_STATUSES = {completed, failed, cancelled}`，运行侧用 `TERMINAL_RUN_STATUSES = {success, failed, skipped, interrupted}` + `ACTIVE_RUN_STATUSES = (queued, running)` 常量集中管理，供 `cancel_stuck_once_tasks`、`mark_stale_active_runs` 等崩溃恢复方法复用。
- 输出约定：所有查询返回 `dict[str, Any]`，由 `_row_to_dict` 将 Row 转为字典并将 datetime 字段经 `deerflow.utils.time.coerce_iso` 序列化为 ISO 字符串，保证对外接口稳定。
