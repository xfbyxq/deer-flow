模块采用「纯状态 + 纯渲染 + 运行时桥接 + UI 应用」四层分离：
- `view_state.py` 定义不可变 `Row`/`Action` 数据类与单一 `reduce(state, action)` 函数，是纯 Python 可测试的核心；
- `render.py` 仅依赖 Rich，把 `ViewState` 转为 `RenderableType`，不引入 Textual；
- `runtime.py` 通过 `_ClientLike` Protocol 解耦 `DeerFlowClient.stream()`，将底层 `StreamEvent` 翻译为 reducer 动作，并保证每次运行以 `RunStarted`…`RunEnded` 包裹；
- `app.py` 中的 `DeerFlowTUI(App)` 持有唯一 `ViewState`，在 Textual worker 线程中驱动 `stream_actions`，并通过 `call_from_thread` 把动作折叠回 UI 线程；`SelectScreen` 作为通用模态对话框复用。
- 入口层 `cli.py` 的 `plan_launch` 是纯决策函数，根据 TTY/环境变量决定 `tui/print/json/headless-help` 模式，延迟导入 `deerflow.tui.app` 以避免缺少 textual 时影响 headless 路径；`__main__.py` 暴露 `python -m deerflow.tui`。
- 辅助子层：`command_registry.py` 合并内置命令与已启用 skill 生成 `/` 补全列表；`session.py` 封装 `DeerFlowClient` 构造、`--resume/--continue` 线程解析以及可选的 `threads_meta` 持久化 writer；`persistence.py` 维护后台 DB loop 与 `ThreadMetaWriter`；`theme.py` 集中主题符号与颜色；`input_history.py` 提供输入历史上下导航；`widgets/composer.py` 封装 Composer 输入框；`message_format.py` 负责工具调用详情格式化。
依赖方向：`app → runtime/view_state/render/theme/command_registry/session/persistence/widgets`，`runtime` 和 `render` 只依赖 `view_state`，彼此互不引用，形成清晰的单向边界。
