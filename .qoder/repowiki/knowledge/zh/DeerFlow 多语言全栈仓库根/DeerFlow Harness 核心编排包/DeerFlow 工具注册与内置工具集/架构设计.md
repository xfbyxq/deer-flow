模块以 `tools.py` 的 `get_available_tools()` 为唯一装配入口，按以下顺序拼接并去重：
- 从 `AppConfig.tools` 通过 `resolve_variable(cfg.use, BaseTool)` 动态导入的工具；若当前运行在 LocalSandboxProvider 下则通过 `_is_host_bash_tool` 剔除 host-bash 工具。
- 内置工具列表 `BUILTIN_TOOLS`（present_file、ask_clarification），并在 `skill_evolution.enabled` 时追加 `skill_manage_tool`；当 `subagent_enabled=True` 时追加 `SUBAGENT_TOOLS`（task）；根据模型是否支持 vision 条件加入 `view_image_tool`。
- 通过 `ExtensionsConfig.from_file()` 读取最新 MCP 配置，调用 `deerflow.mcp.cache.get_cached_mcp_tools()` 获取缓存工具并用 `mcp_metadata.tag_mcp_tool` 打上 `deerflow_mcp` 标记，供后续 `tool_search.py` 与 agent 构建侧识别。
- 若存在 ACP 代理配置则通过 `invoke_acp_agent_tool.build_invoke_acp_agent_tool` 动态组装 ACP 工具。
- 所有工具经 `_ensure_sync_invocable_tool` + `sync.make_sync_tool_wrapper` 包装，使异步协程可在同步 Agent 路径中执行；最终按 `.name` 去重，冲突项记录警告日志。

子目录 `builtins/` 是纯工具实现（clarification/present_file/task/view_image/setup_agent/update_agent/invoke_acp_agent/tool_search），由 `__init__.py` 统一导出；`types.py` 定义全局 `Runtime = ToolRuntime[dict[str, Any], ThreadState]` 作为所有工具的运行时类型契约；`mcp_metadata.py` 集中维护 MCP 标记键与读写谓词，避免魔法字符串散落。依赖方向单向：工具 → tools 装配器 → config/mcp/cache/sandbox/security，无反向引用。
