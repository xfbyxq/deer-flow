本模块由三个职责正交的纯函数/类文件组成，共同构成 harness 在脱离 FastAPI 应用时仍可独立评估和继续运行的核心：
- `goal.py`：实现 Claude Code 风格的 goal loop 原语。通过 `GoalState`（来自 `deerflow.agents.goal_state`）承载活跃目标，使用 `create_goal_evaluator_model` + `evaluate_goal_completion` 调用一个非 thinking 的 chat model 对可见对话证据做 JSON 结构化评估；`should_continue_goal` / `compute_no_progress_count` / `latest_visible_assistant_signature` 组合出“无进展”断路器；`read_thread_goal` / `write_thread_goal` 借助 `_call_checkpointer_method` 以 async/sync 双适配方式读写 LangGraph checkpointer 的 `channel_values['goal']`，并通过 `expected_checkpoint_id` 与 `uuid6()` 生成新 id 实现乐观写冲突检测；`goal_thread_lock` 基于 `WeakKeyDictionary[EventLoop, dict[thread_id, asyncio.Lock]]` 按 event loop 隔离串行化。
- `journal.py`：`RunJournal(BaseCallbackHandler)` 作为 LangChain 回调中间件，将 `on_chain_start/end/error`、`on_chat_model_start`、`on_llm_end`、`on_tool_end` 等事件标准化为 `{thread_id, run_id, event_type, category, content, metadata}` 结构的 RunEvent，写入可插拔的 `RunEventStore`；内部维护缓冲队列、去重集合、按 caller 标签 (`lead_agent`/`subagent:{name}`/`middleware:{name}`) 分桶的 token 累计器，并提供 `record_external_llm_usage_records` 供外部来源补充用量；`flush` 与 `_schedule_progress_flush` 负责异步批量落盘与节流进度快照。
- `serialization.py`：提供 `serialize_lc_object` 递归把 Pydantic v1/v2、LangGraph `Interrupt`、普通对象转成 JSON 安全结构；`serialize_channel_values` 剥离 `__pregel_*` 内部键；`strip_data_url_image_blocks` 从 `hide_from_ui` 消息中剔除 `data:` scheme 的 base64 图片块，防止大响应体泄漏；三者组合为 `serialize(obj, mode='messages'|'values')` 入口，被 worker SSE 发布与 REST 线程路由消费。
依赖方向：本模块仅向上依赖 `deerflow.agents.goal_state`、`deerflow.models`、`deerflow.utils.*` 与 LangChain/LangGraph SDK，不反向依赖任何 web 层或具体存储实现。
