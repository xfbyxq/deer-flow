- 对外暴露的 API 同时支持同步与异步 checkpointer：通过 `_call_checkpointer_method` 用 `inspect.isawaitable` 探测并 `asyncio.to_thread` 包装阻塞调用，避免在事件循环上执行 IO。
- 所有用户输入文本在进入持久化前都经过白名单/长度截断：`normalize_goal_objective` 限制 4000 字符，`_normalize_evaluation_text` 限制 reason/evidence_summary，`_message_text` 截取 2000 字符，且均先做空白归一化。
- LLM 回调中的 token 用量统计一律以 langchain run_id 为去重键（`_counted_llm_run_ids` / `_counted_message_llm_run_ids` / `_counted_external_source_ids`），防止重复回调导致重复计数。
- 事件类型采用 `run.start` / `llm.ai.response` / `llm.tool.result` / `middleware:{tag}` 等带命名空间的字符串常量，并通过统一的 `_put(event_type, category, content, metadata)` 写入缓冲队列。
- JSON 解析结果一律显式校验字段类型后再构造数据类：`parse_goal_evaluation_response` 对 `satisfied` 要求 bool、对 `blocker` 走 `_normalize_goal_blocker` 白名单回退到 `missing_evidence`。
- 面向 UI 的数据返回路径必须剥离敏感内容：`strip_data_url_image_blocks` 只处理 `hide_from_ui=True` 的消息中的 `data:` 图片块，`serialize_channel_values` 丢弃 `__pregel_*` 内部键。
