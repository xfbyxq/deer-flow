模块按职责拆分为四个子层：
- `schemas.py` 定义 `RunStatus`（pending/running/success/error/timeout/interrupted）和 `DisconnectMode`（cancel/continue_）两个 StrEnum，作为跨层契约。
- `store/base.py` 抽象出 `RunStore` 接口（put/get/list_by_thread/update_status/update_run_completion/aggregate_tokens_by_thread 等），所有持久化路径通过该接口访问；`store/memory.py` 提供基于 dict + thread_id 二级索引的内存实现，供默认后端与测试使用。
- `manager.py` 是核心：`RunManager` 维护进程内 `_runs` 字典与 `_runs_by_thread` 有序索引，用 `asyncio.Lock` 保护所有写操作，并可选注入 `RunStore` 做持久化；`create_or_reject` 在锁内原子完成“检查同线程 inflight + 插入”，支持 `reject/interrupt/rollback` 三种 multitask 策略；`shutdown` 在进程退出时 bounded 等待 in-flight task 结束，避免 langgraph checkpointer 连接池关闭后的未捕获异常；SQLite 压力通过 `_call_store_with_retry` + `PersistenceRetryPolicy` 指数退避处理。
- `worker.py` 暴露 `run_agent(bridge, run_manager, record, ctx, agent_factory, ...)` 入口，将 run 包装成 asyncio.Task 驱动 `agent.astream(...)`，把 values/updates/messages/custom 事件经 `StreamBridge` 推送 SSE，并在 finally 中统一刷新 journal、记录 workspace 变更、同步 thread title/status、清理 abort 标记；内部还包含 `_SubagentEventBuffer` 对 subagent step 事件做批量落盘，以及 goal 自动续转逻辑（读取/评估 goal → 必要时写入新的 continuation input）。
- `naming.py` 提供 `resolve_root_run_name`，从 config/context/configurable 中解析根 run 名称用于 LangSmith/Langfuse 追踪。
依赖方向：worker → manager → store.base；schemas/naming 被 worker 与 manager 共同消费，无循环依赖。
