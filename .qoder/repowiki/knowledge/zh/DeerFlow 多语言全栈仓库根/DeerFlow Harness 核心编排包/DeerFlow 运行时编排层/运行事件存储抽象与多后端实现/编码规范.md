- 所有查询方法对 `before_seq` / `after_seq` 采用一致的游标分页语义：`after_seq` 返回 seq > after_seq 的前 limit 条（正向翻页），`before_seq` 返回 seq < before_seq 的最后 limit 条（反向翻页），二者都不时返回最新 limit 条。
- 写入路径统一先执行 `_truncate_trace`（按字节截断 category=trace 的内容并在 metadata 中标记 `content_truncated` / `original_byte_length`）再序列化入库，保证 trace 不撑爆存储。
- DB 读路径通过 `resolve_user_id(user_id, method_name=...)` 从上下文变量注入 user_id 过滤，未设置时自动跳过以兼容后台 worker 与 HTTP 请求两种调用场景。
- 每个方法签名都使用 keyword-only 参数（`*, thread_id=..., run_id=...`）并通过 `**ev` 透传给 `put_batch`，使批量写入与单条写入共享同一记录结构。
