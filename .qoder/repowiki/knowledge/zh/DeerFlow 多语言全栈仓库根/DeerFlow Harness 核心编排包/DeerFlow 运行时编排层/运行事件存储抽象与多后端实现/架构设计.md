模块采用「抽象接口 + 工厂 + 多后端实现」的分层结构：
- `store/base.py` 定义 `RunEventStore` 抽象类，统一 `put` / `put_batch` / `list_messages` / `list_events` / `list_messages_by_run` / `count_messages` / `delete_by_thread` / `delete_by_run` 等异步方法，约定 `seq` 在同一 thread_id 内严格递增、`category=message` 的事件用于前端展示。
- `store/memory.py`、`store/db.py`、`store/jsonl.py` 分别给出三种实现：进程内 dict + bisect 投影（开发/测试）、基于 SQLAlchemy ORM 的 `run_events` 表（生产，支持 PostgreSQL advisory lock 解决 max(seq) 并发问题并截断 trace 内容）、单进程 JSONL 文件（`.deer-flow/threads/{thread_id}/runs/{run_id}.jsonl`，通过 `asyncio.Lock` 串行写）。
- `store/__init__.py` 暴露 `make_run_event_store(config)` 工厂，根据配置 `backend ∈ {memory, db, jsonl}` 动态选择实现；`db` 模式在 `persistence.engine.get_session_factory()` 不可用时回退到 memory。
- 顶层 `events/__init__.py` 仅重新导出 `RunEventStore` 与 `MemoryRunEventStore`，作为外部入口。
依赖方向单向：具体实现 → base 抽象 → 上层调用方；DB 实现额外依赖 `persistence.models.run_event.RunEventRow`、`user_context` 与 `utils.time.coerce_iso`。
