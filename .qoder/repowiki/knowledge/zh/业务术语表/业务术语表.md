### Ultra 模式
- 定义：DeerFlow 对话模式之一，启用 thinking + plan mode + sub-agent 委派，reasoning_effort = high，代表完整能力。需要模型声明 supports_thinking: true 才能使用，否则前端会自动降级为 Flash 模式。
- 别名：ultra、ultra模式

### Pro 模式
- 定义：DeerFlow 对话模式之一，启用 thinking + plan mode，reasoning_effort = medium。相比 Ultra 模式缺少 sub-agent 委派功能。
- 别名：pro、pro模式

### Thinking 模式
- 定义：DeerFlow 对话模式之一，启用 thinking，reasoning_effort = low。比 Pro 和 Ultra 模式轻量，不包含 plan mode。
- 别名：thinking、thinking模式

### Flash 模式
- 定义：DeerFlow 对话模式之一，关闭 thinking，最快响应。当模型不支持 thinking 时，其他模式会自动降级为此模式。
- 别名：flash、flash模式

### supports_thinking
- 定义：模型配置字段，声明模型是否支持 thinking 推理能力。当前端检测到模型此属性为 false 时，会强制将所有高级模式降级为 Flash 模式，导致 Ultra/Pro/Thinking 模式无法选择。
- 别名：supports_thinking、thinking支持

### ACP Agent
- 定义：通过 ACP 协议调用的外部独立智能体进程，如 Claude Code、Codex 等。与 Sub-Agent 不同，ACP Agent 运行在独立子进程中，具有隔离的工作空间和独立的执行环境。
- 别名：acp agent、外部智能体

### Sub-Agent
- 定义：DeerFlow 内部的多智能体协作机制，在同一进程内的 LangGraph 子图中运行，共享沙箱环境。与 ACP Agent 的跨进程通信不同，Sub-Agent 使用 LangGraph 内部协议。
- 别名：sub-agent、子智能体

### acp-workspace
- 定义：ACP 外部智能体的独立工作空间目录，每个会话线程拥有隔离的 workspace。主智能体对 /mnt/acp-workspace/ 只有读取权限，ACP 子进程从宿主机侧写入结果，产出文件需要 cp 到 /mnt/user-data/outputs/ 后才能交付给用户。
- 别名：acp-workspace、ACP工作空间

### 用户隔离
- 定义：DeerFlow 的智能体、线程、记忆等数据按用户隔离存储的机制。自定义智能体现在存储在 {base_dir}/users/{user_id}/agents/{name}/ 目录下，每个用户只能看到自己 user_id 目录下的智能体。旧版共享布局 .deer-flow/agents/ 仍作为只读回退存在。
- 别名：用户隔离、per-user、用户隔离机制

### get_effective_user_id()
- 定义：DeerFlow 中解析当前有效用户 ID 的核心函数，从认证上下文中获取 user_id，无认证模式下默认为 'default'。该函数决定了文件系统隔离的用户桶路径。
- 别名：get_effective_user_id、effective_user_id

### mimo-v2.5
- 定义：小米 MiMo V2.5 模型，在 DeerFlow 中通过 PatchedChatMiMo 提供商接入，base_url 指向 https://token-plan-cn.xiaomimimo.com/v1。该模型实际支持 thinking 功能，但需要正确配置 supports_thinking: true 才能在 Ultra 模式中启用。
- 别名：mimo-v2.5、MiMo V2.5、小米模型
