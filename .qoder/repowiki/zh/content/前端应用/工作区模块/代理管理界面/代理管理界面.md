## 简介
本文件面向“代理管理界面”的开发者与使用者，系统性阐述以下能力：
- 代理列表展示：卡片渲染、搜索过滤与排序机制
- 代理创建流程：表单验证、配置模板与API调用
- 代理编辑功能：属性修改、权限设置与版本管理
- 状态监控：运行状态显示、性能指标与错误日志
- 批量操作：启用/禁用、删除、导入/导出
- 最佳实践与常见问题解决方案

## 项目结构

## 架构总览
代理管理的前后端交互遵循“页面 -> 列表 -> 卡片 -> Hooks -> API -> 路由 -> 服务 -> 依赖”的分层模式。

```mermaid
sequenceDiagram
participant U as "用户"
participant P as "页面 page.tsx"
participant L as "列表 AgentList.tsx"
participant H as "Hooks hooks.ts"
participant A as "API api.ts"
participant R as "路由 agents.py"
participant S as "服务 services.py"
participant D as "依赖 deps.py"
U->>P : 打开代理管理页
P->>L : 渲染列表并传入查询参数
L->>H : 触发数据加载(搜索/分页/排序)
H->>A : 发起HTTP请求
A->>R : GET/POST/PUT/DELETE /agents
R->>S : 调用服务方法
S->>D : 访问存储/外部系统
D-->>S : 返回结果
S-->>R : 序列化响应
R-->>A : JSON 响应
A-->>H : 解析并缓存
H-->>L : 更新UI状态
L-->>U : 展示代理卡片
```

### 代理列表展示
- 卡片渲染
  - 展示字段：名称、标识、状态、更新时间等
  - 交互：点击跳转详情、快捷操作（启用/禁用、删除）
  - 视觉：空态、骨架屏、错误提示
- 搜索过滤
  - 支持按名称、标签、状态等条件筛选
  - 防抖与分页联动，避免频繁请求
- 排序机制
  - 支持按时间、名称、状态等维度排序
  - 排序键与方向由查询参数驱动

```mermaid
flowchart TD
Start(["进入代理列表"]) --> LoadParams["读取URL查询参数<br/>搜索/分页/排序"]
LoadParams --> FetchData["调用hooks获取数据"]
FetchData --> DataReady{"数据就绪?"}
DataReady --> |否| ShowSkeleton["显示骨架屏"]
DataReady --> |是| RenderCards["渲染代理卡片"]
RenderCards --> UserAction{"用户操作"}
UserAction --> |搜索/排序| UpdateParams["更新查询参数"]
UpdateParams --> FetchData
UserAction --> |翻页| FetchData
UserAction --> |选择卡片| NavigateDetail["跳转到详情页"]
ShowSkeleton --> End(["完成"])
RenderCards --> End
```

### 代理创建流程
- 表单验证
  - 必填项校验、格式校验、唯一性检查
  - 实时反馈与提交前二次确认
- 配置模板
  - 提供常用模板快速填充
  - 模板变量替换与默认值策略
- API 调用
  - 使用统一的API客户端发送创建请求
  - 成功后刷新列表并导航至详情页

## 依赖关系分析
- 前端耦合度
  - 页面与列表低耦合，通过 props 与 hooks 解耦
  - API 客户端集中管理，便于统一错误处理与拦截器扩展
- 后端分层
  - 路由仅负责协议转换与鉴权，业务逻辑下沉至服务层
  - 依赖注入用于数据库、缓存、消息队列等外部资源
- 潜在循环依赖
  - 确保 hooks 不直接依赖页面组件，API 不依赖 UI 状态
